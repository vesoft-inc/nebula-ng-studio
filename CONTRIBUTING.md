# Contributing

Thank you for contributing to NebulaGraph Studio.

## Repository guidance

Read [AGENTS.md](AGENTS.md) for repository-wide rules and task-specific guides. Shared package contracts and lessons are maintained in [docs/agents](docs/agents).

## Tech stack

- [Turborepo](https://turbo.build/repo/docs) for managing multiple packages
- [React](https://reactjs.org/) for building user interfaces
- [TypeScript](https://www.typescriptlang.org/) for static type checking
- [MUI](https://mui.com/) for UI components
- TanStack Router file routes for Web/GUI (see [Web routing](apps/web/README.md) and [GUI routes](apps/gui/src/routes))
- [MobX](https://mobx.js.org/) for state management
- [Emotion](https://emotion.sh/) for styling
- [Tailwind CSS](https://tailwindcss.com/) for utility-first styling
- [Vite](https://vitejs.dev/) for bundling and dev server
- [ESLint](https://eslint.org/) for linting
- [Prettier](https://prettier.io) for code formatting
- [pnpm](https://pnpm.io/) for package management
- [Go](https://go.dev/) and [go-zero](https://go-zero.dev/) for the Studio Server
- Docker/Compose for the primary self-hosted distribution

## Prerequisites

- Node.js 22 or later, matching the root `engines` declaration. CI uses Node.js 24.21.0 by default.
- pnpm 9.12.2, matching the root `packageManager` field.
- Go 1.25.0 or later for Server work; the module selects the Go 1.25.14 toolchain used by CI.
- Docker Engine 20.10+ and Docker Compose v2.20+ only when working on the container path.

Install locked dependencies without running repository-specific generators:

```bash
pnpm install --frozen-lockfile
go -C apps/server mod download
```

## Local development

Run the Studio Server and frontend in separate terminals:

```bash
pnpm dev:server
pnpm dev
```

`pnpm dev:server` loads [`apps/server/etc/config-dev.yaml`](apps/server/etc/config-dev.yaml). The Studio dev server runs at <http://127.0.0.1:3000> and proxies `/api` to the Server at <http://127.0.0.1:7001>. Graphd is external; enter an address reachable from the Server process on the login page.

## Repository checks

Use the narrowest relevant command while developing, then run the full repository checks before opening a PR:

```bash
pnpm format:check
pnpm lint
pnpm -r --if-present lint:types
pnpm test
go -C apps/server test ./...
```

All Node workspaces use the root `pnpm-lock.yaml`; package-local npm lockfiles are not used. The ordinary test suites and public CI do not require an external database.

## Builds

Production build entry points are:

```bash
pnpm build
pnpm build:server
```

`pnpm build` builds Studio into `apps/web/dist`, then runs its separate `copy:server` script to replace `apps/server/assets/public` with the Web output served by the Studio Server. Neither the Web output nor the copied Server assets are tracked.

`pnpm build:server` first builds and stages the Studio frontend, then writes the Server binary to `apps/server/bin/studio`. Run the local binary from `apps/server` with `./bin/studio -f etc/config-dev.yaml` so its fixed `assets/public` path resolves correctly and it uses the development configuration.

## Integration profile

An environment with Graphd credentials can run the opt-in integration profile against an already healthy Studio Server:

```bash
STUDIO_INTEGRATION_BASE_URL=http://127.0.0.1:7001 \
STUDIO_INTEGRATION_GRAPHD_ADDRESS=host.docker.internal:9669 \
STUDIO_INTEGRATION_GRAPHD_USERNAME='<username>' \
STUDIO_INTEGRATION_GRAPHD_PASSWORD='<password>' \
pnpm test:integration:graphd
```

The profile validates login/session creation, user info, Query, Schema, Explorer Graphd and Snapshot API access, logout, and rejection of the old session. Missing variables fail the explicit profile instead of silently skipping it.

## Server API generation

`internal/handler` and `internal/types` are generated by goctl v1.8.5, and `internal/handler` also carries hand-written customizations. Never regenerate in place: produce a complete reference result in a scratch directory outside the repository (copy the module metadata, `restapi/` and `.goctl/` there first):

```sh
go run github.com/zeromicro/go-zero/tools/goctl@v1.8.5 api go -api ./restapi/studio.api -dir . -style gozero -home ./.goctl
```

Review the full generated diff and copy back only the intended change — routes, generated types and new files. Never use `latest` or a globally installed goctl.

## Changes and pull requests

- Create a focused branch and keep commits scoped to one concern; do not mix generated caches or unrelated formatting into a commit.
- Update the relevant docs and lockfile with behavior or dependency changes.
- Explain compatibility, database migration, configuration, and user-visible effects in the PR description.
- Never commit credentials, deployment-owned configuration, private endpoints, or generated artifacts.
